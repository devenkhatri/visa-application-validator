The Challenge

The current process is causing bottlenecks and inefficiencies
It needs urgent improvement

Visa consultancies today rely on manual document review — a slow, inconsistent, and error-prone process that limits how many applications can be handled and increases the risk of avoidable rejections.

⏱️
Speed
3–4 hours per application
Consultants manually check every document against each country's requirements. A single application review takes 3–4 hours. At scale, this becomes a bottleneck that limits business growth and forces hiring of more staff just to keep up.
⚖️
Consistency
Human error and inconsistency
Different consultants apply different standards. Junior staff miss requirements. Checklists go out of date. The quality of a review depends entirely on who is doing it on that particular day — and on how busy they are.
📉
Outcome
Avoidable rejections
Applicants submit with missing or weak documents that a thorough review would have caught. Rejections damage the consultancy's reputation, require costly reapplication processes, and erode client trust built over years.
The Solution

How the system
works — six steps

A six-step AI pipeline processes every visa application automatically. OCR runs locally on your machine — documents never leave your infrastructure. Only anonymised summaries reach the cloud AI for analysis.

1
Document Intake
Applicant uploads their documents
The applicant or agent uploads visa documents through the web portal — passport scans, bank statements, employment letters, photographs, and supporting documents. Files are accepted as PDF, JPG, or PNG (max 10MB each). Each file is immediately fingerprinted using an MD5 hash for the caching system. In production, files are stored securely in the client's own Google Drive or OneDrive — the application never touches any third-party permanent storage. In the MVP demo, files are stored temporarily in PostgreSQL for simplicity.
📂 Google Drive API ☁️ OneDrive API 🔐 AES-256 Encryption 🔍 MD5 Fingerprinting
2
OCR Cache Check
Smart caching avoids reprocessing identical documents
Before running any OCR, the system checks two cache layers using the document's MD5 hash. First, the Neon PostgreSQL database is checked — if this exact document has been processed before (within 90 days), the stored extraction is returned instantly at zero OCR cost. The local Python service also maintains a SQLite cache. This means resubmissions, partial application updates, and repeated demo runs all benefit from instant cache hits — no OCR engine is invoked at all. The 90-day cache covers virtually all reapplication scenarios.
⚡ Neon PostgreSQL cache 🗄️ Local SQLite cache 🔍 MD5 hash lookup 💰 Cache hit = ₹0 cost
3
Local OCR Extraction — New in v2.0
Documents read locally — nothing leaves your machine
On a cache miss, the document is processed by a Python FastAPI service running locally on your server — never sent to any cloud API. PaddleOCR (the default engine) achieves 88–94% accuracy and supports multilingual passports including Arabic, Hindi, Urdu, and Chinese. For higher accuracy on complex documents, Ollama with the minicpm-v vision model can be used, achieving near-API quality with zero internet dependency. Tesseract is available as a lightweight fallback. All three engines run entirely offline after an initial one-time model download. The extracted text is then parsed into structured JSON fields per document type.
🔒 100% Local — no internet 🐍 Python FastAPI service 🎯 PaddleOCR (default) 🤖 Ollama (high accuracy) 🌍 Multilingual support 💰 ₹0 per document
4
Privacy Protection
PII Scrubber removes all sensitive identifiers before cloud
Before any data is sent to Claude for analysis, it passes through the PII Scrubber — a critical data transformation layer that runs locally. Passport numbers become has_passport_number: true. Exact bank balances become financial_range: "medium". Full names, account numbers, dates of birth, exact salary figures, and home addresses are all removed or converted to banded ranges. Combined with local OCR, this means: (a) the raw document never leaves your machine, and (b) even the extracted data is anonymised before going to the cloud. Claude never sees a single real personal identifier.
🛡️ scrubPII() — runs locally 🚫 No raw PII to cloud 📊 Banded ranges only ✅ GDPR simplified
5
AI Gap Analysis
Claude analyses anonymised summaries against the visa checklist
Claude Sonnet 4.6 — Anthropic's most capable everyday model — receives only the scrubbed summaries alongside the country-specific visa checklist. It acts as an expert visa officer with 20 years of experience, evaluating each requirement against what has been submitted. Claude returns a fully structured JSON response: gap analysis with severity ratings per item, an overall probability score from 0 to 100, a breakdown across five weighted components (document completeness 30%, financial strength 25%, travel history 20%, ties to home country 15%, application quality 10%), a verdict (strong / moderate / weak / insufficient), key strengths, critical gaps, and recommended actions. Prompt caching reduces per-application AI cost by up to 90%.
🧠 Claude Sonnet 4.6 📋 Country checklist matching 💡 Prompt caching (90% saving) 📊 5-component score (0–100)
6
Report Delivery
Full report delivered — interactive, PDF, and email
The complete gap analysis report is displayed on an interactive dashboard with an animated probability score gauge, a sortable gap analysis table, a bar chart of the five score components, key strengths, critical gaps, and a numbered list of recommended actions. The report is generated as a downloadable PDF using @react-pdf/renderer (Vercel-compatible — no Puppeteer needed) and saved back into the applicant's folder in Google Drive or OneDrive. An email notification is sent via Resend to both the agent and the applicant. The entire process from upload to completed report takes under 3 minutes.
📊 Interactive dashboard 📄 PDF download 📧 Email via Resend ☁️ Saved to Drive/OneDrive

Local OCR — New in v2.0

Documents never leave
your infrastructure

Unlike cloud OCR services, our local OCR service runs as a Python sidecar on your own server. Three engine options — choose based on your hardware and accuracy requirements. Switch to Mistral cloud API with one environment variable if ever needed.

🎯
PaddleOCR
Default engine — best balance of speed and accuracy
Open source OCR built by Baidu, excellent for multilingual identity documents. Downloads ~100MB model on first run, then works fully offline. Handles rotated text, stamps, and complex layouts. Supports Arabic, Hindi, Urdu, Chinese, English and more.
Accuracy88–94%

Ollama + minicpm-v
Vision LLM — highest quality, structured JSON output
Run a vision-capable AI model entirely locally using Ollama. Reads the document image and returns structured JSON directly — no text parsing needed. Near-API quality. Requires more RAM but delivers the most accurate structured extraction for complex documents.
Accuracy90–96%

Tesseract
Lightweight fallback — instant setup
The classic open-source OCR engine. Minimal setup, works on any hardware, no model downloads required. Lower accuracy on complex layouts and handwritten content, but a reliable fallback for clean printed documents. Good for initial testing.

For maximum privacy: deploy the Python OCR service on the customer's own server. For simpler operations: switch to Mistral API with a signed DPA. The choice can be made at any time — the architecture supports both.
